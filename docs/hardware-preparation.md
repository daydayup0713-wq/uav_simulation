# 真机接入准备

当前交付包含配置模板和只读检查入口，尚未验证真实 Pixhawk 6X、Mid-360、相机、RTK 或机载计算机。仿真中的机型、质量、惯量、测量噪声与固定优化参数不能直接代表实机。

复制 `configs/hardware/pixhawk6x.template.json` 到自己的配置文件。填入实际 firmware commit、XRCE 传输、机载计算机架构、整机质量/外形/惯量、传感器外参、标定版本及来源、测量源时钟契约、时钟误差、延迟与 ENU 地理边界。相机内参/畸变、相机光学外参、RTK 天线杆臂与各硬件输出数据契约还需随具体后端核对。外参为母坐标系表达的 xyz/rpy，平台 ENU/FLU；只有飞控适配层处理 NED/FRD。

```bash
./scripts/env.sh /usr/bin/python3 scripts/check_hardware.py configs/hardware/pixhawk6x.template.json
# 原始模板预期返回非零并列出缺失参数。
```

检查不创建 ROS 上下文、无飞控发布、无解锁或起飞行为。`ready` 只表示所检查的静态基础字段完整，输出始终 `hardware_flight_qualified: false`。相机/RTK 参数、实际固件和时序仍须根据所选硬件及算法验收；字段填写不是测量验证。

部署时用目标机系统 ROS Humble/Python 与新的独立前缀重新构建。后端二进制、链接库、源树、配置和 ABI 在目标机重新生成摘要；不直接复制本机 x86 优化的 ORB/GLIM/规划器二进制。Agent 2.4.3 私有安装匹配目前 PX4 Client 2.4 系列；实际固件升级需重新验证消息与版本化话题，不能只修改版本字符串。

接入顺序为硬件数据采集与标定、固定数据回放、实时地面定位/质量检查、飞控未解锁通信与时间/坐标验证、受控起降、悬停、低速航线、障碍与故障验证。唯一飞控适配器、显式解锁、地面选择、陈旧状态拒绝、失效降落和不自动续飞机制保留。Gazebo 真值接口不属于真机定位输入。

现有 `start_lab.sh` 是仿真监督入口；本轮没有把它自动重定向到真实飞控，也没有开启未验证的硬件飞行入口。实机运行监督器和试飞策略应在实际参数、连接与受控试验条件确认后接续开发。
