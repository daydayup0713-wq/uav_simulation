# 增量版本路线

最终数据链：传感器采集 → SLAM → 自主导航 → 点位巡检 → AI 检测 → 数字孪生更新。旧学习包、Edge、Cloud 仅作参考，新平台独立构建。单机单无人机为默认资源配置，传感器使用低分辨率，AI/重建以离线作业为主。

| 等级/版本 | 交付 | 下一阶段门槛 |
|---|---|---|
| L0 V0.1 | 干净依赖、监督进程、适配、CLI、起降航点、轨迹 | 三次自动演示、故障测试、安装复现 |
| L1 V0.2.0 | 通用实验室几何、三维雷达、IMU、相机、TF、rosbag、独立真值 | 频率、源时间、标定、回放验证 |
| L1 V0.2.1 | Mid-360 扫描近似、逐点时间、噪声、外参 | 数据契约和近似限制明确 |
| L1 V0.3.0 | 点云配准学习实验、LIO 适配、六自由度里程计 | 固定数据集轨迹误差和质量量化 |
| L1 V0.3.1 | 回环、保存/加载、重定位、外部里程计输入 PX4 | 无 GNSS 飞行；LIO 和完整 SLAM 分开验收 |
| L1 V0.4 | 三维障碍地图、规划、轨迹约束、碰撞检查 | 绕障；不可达目标确定返回 |
| L2 V0.5 | 巡检点、姿态调整、采集、暂停/恢复/取消 | 多点任务可重复完成 |
| L2 V0.6 | Web 实验台、遥测、轨迹、任务配置、控制权 | 网页与底层状态一致，断连处理 |
| L3 V0.7 | 仪表/病害插件、证据、图像与位姿关联、三维定位 | 可追溯；演示与真实精度分开报告 |
| L3 V0.8 | 数据导出、Mesh/3DGS、空间配准、孪生图层 | 原始数据关联和空间对齐验证 |
| L3 V0.9 | 完整巡检、故障注入、性能与长期测试 | 端到端验收 |
| V1.0 | 接口冻结、安装、基准场景、发布文档 | 干净主机完整复现 |
| V2.0 | Pixhawk 6X、真实 Mid-360/相机、机载部署、试飞 | 配置切换和受控试验 |
| V3.0 | 场站模板、多机、资产、历史病害、权限、运维 | 项目级运营 |

自主算法先建立固定数据集回放基准，再进入实时闭环。每一算法阶段首先比较数据契约、Humble 构建和本机性能，然后固定版本。场景从通用实验室扩展到电厂、隧道、桥梁。

真实尺寸、质量、惯量、载荷和标定尚未提供。几何、动力学、传感器、时延、任务行为需分别校准，V0.x 是学习与验证模型。

自主系统用连续 odom 控制；未来增加 map → odom，回环不能直接跳变控制目标。Gazebo 真值只输入评估器。数据保存运行编号、配置、版本、标定与变换。数字孪生分为导航几何、实景展示和业务标注；3DGS 展示与导航障碍地图分开，测量附带几何来源及误差依据。

每个版本执行：接口与验收设计 → 小步 PR → 自动测试 → 本机演示 → 记录限制 → 发布标签。版本升级以前版回归通过为条件。
