# V0.1 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. Track verification in docs/IMPLEMENTATION_STATUS.md.

**Goal:** Implement the independently buildable PX4 flight lab and verify real SITL acceptance.
**Architecture:** Pure Python flight policy owns transitions and limits. ROS adapter owns DDS and public services/actions. A supervisor owns only its processes and archives each run.
**Tech Stack:** Humble, Harmonic, PX4, rclpy, Python 3.10, pytest, CMake.
**Spec:** ../specs/2026-10-01-uav-lab-design.md

## Global Constraints

- Fixed commits in dependencies/lock.json; no changes to existing PX4/ROS projects.
- ENU/FLU outside PX4 boundary; only bridge publishes PX4 inputs.
- Single simulated UAV; 20 Hz heartbeat; warmup 2 s; explicit arm.
- Target speed <=1m/s; tolerance 0.3m continuously 2s.
- Do not tag a release until three real flights and fault acceptance pass.

## Review Focus

- Stale telemetry prevents flight, even when cached pose looks valid.
- ACK alone must not report arm/mode/land success.
- A canceled goal must not overwrite a new landing goal.
- Clock regression and firmware restarts cannot resume an old flight.
- Startup/cleanup must not take over or terminate unrelated processes.
