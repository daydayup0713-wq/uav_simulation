# V0.3 算法选型与固定数据基准

冻结 [GLIM v1.1.0](https://github.com/koide3/glim/tree/v1.1.0)、同版本 gtsam_points 与 glim_ros2；具体提交见 `dependencies/lock.json`。本机 Humble/GTSAM4.2 CPU 构建已通过，关闭 CUDA、可视化依赖和图像算法，每个优化模块两线程。

GLIM 的 GICP/IMU 固定窗口用于连续 LIO，子地图位姿图用于全局回环。`odom_corrected` 是点云更新后的**连续局部**位姿；`pose` 才包含全局地图修正。ROS 上游 twist 为世界速度，平台转换为 FLU body twist。v1.1 不提供 ROS 边缘协方差，平台显式声明配置的 EKF 观测噪声下限，不能把它解释为实测定位精度。

当前雷达无逐点时间，配置 `global_shutter_lidar=true`。上游 TimeKeeper 可能打印生成伪时间的提示，但随后 CloudPreprocessor 将所有逐点时间清零，因此不用于去畸变。IMU 的理想姿态标记为不可用，输入只有角速度、加速度与同步点云。

FAST_LIO 的 ROS2 适配需要进一步处理点字段/雷达预处理，也不直接交付完整回环与地图管理，因此未作为当前契约的运行后端。这里的比较包含传感器兼容性、Humble 构建以及本机可测性能；不宣称在同一数据集实测了未适配的算法。

固定输入为 V0.2 80秒运动数据集 `20261004T103659Z-5d426e73-104356-128d1b`。算法 bag 只含 `/uav001/lidar/points` 与 `/uav001/imu/data`；真值只由独立评估器读取。清单绑定原始 bag SHA256 和标定，估计轨迹只做一次 SE(3) 对齐，不拟合尺度。

| 方法 | 有效覆盖 | 位置 ATE RMSE | 姿态 RMSE | 用时 |
|---|---:|---:|---:|---:|
| GLIM CPU LIO | 初始化后100%，766帧 | 0.02433m | 0.06339° | 18.46秒，输入79.5秒 |
| GLIM 位姿图 | 同上 | 0.02433m | 0.06336° | 包含在上项 |
| 学习 ICP | 9.31%，74帧 | 0.00263m（仅短暂地面段） | 0.04457°（同段） | 4.64秒后停止 |

学习 ICP 在首段上升时因点到点残差0.161m超过0.15m门限而停止；短地面段误差不能代表完整飞行精度。GLIM 的1秒平移RPE为0.00503m，最大源输出间隔0.1秒。未经对齐的位置误差0.26566m主要含任意局部高度原点，原始值同时保留。

原生优化图有8个子地图、11个因子，其中3条实际非相邻约束为0↔5、1↔5、0↔6。回环候选日志不作为接受证据；原生工具反序列化最终图并读取实际 BetweenFactor。该短路线的局部漂移已很小，全局与局部 ATE 基本相同，不宣称回环明显提升了精度。

实时带 GNSS 对照飞行的一次79秒录制：791帧，ATE0.01364m、姿态0.20703°、延迟P95为0.056秒，最大0.072秒，全段质量READY。此结果验证实时定位；无 GNSS飞行另行验收，不能从此对照实验推断。

重定位目前需要操作者提供接近实际位置的粗位姿，匹配修正限制0.75m/20°，内点≥75%、残差≤0.1m且六自由度可观测。地图可载入和重新定位，不提供无先验的全局失踪恢复。初次实测旧地图对新扫描内点100%、残差0.04855m；地图处理与定位心跳的并发回归覆盖慢IO情况。
