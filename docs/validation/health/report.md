## 稳定性修复及边界

导航健康发布独立于重计算回调，地图提交后即时发布；飞控侧按最新消息接收导航诊断，使用 BEST_EFFORT/depth=1，现有 Reliable 发布者仍兼容 CLI。源时间、接收年龄和首个拒绝原因可查；CPU/RSS/I/O 与计算时间有界采样。300ms 回调阻塞和 QoS 兼容性由真实 ROS 测试复现及验证。

相同诊断订阅条件下十次启动由 9/10 变为 10/10，通过与失败运行及哈希保存在 [启动接收对照](startup-reception.json)。没有放宽源过期阈值，恢复输出不清除保护锁存、不自动解锁或续飞。

另一次故障测试在注入前遇到 GLIM IMU 输入时间间隔 188ms/128ms，已经保留为失败启动，未算作故障通过。原始传感器与接收调度的具体因果尚未定位。有效重试中的独立传感器探针未发现注入前数据间隔，不能据此证明所有超时已消除。

## 用户复验

当前实现和依赖位于独立工作区，进入此处启动，避免误运行原始旧代码：

```bash
cd /home/pine/workspace/ai/UAV/uav_simulation/.worktrees/lab-health
./scripts/workbench.sh
```

若 8780 已在运行，直接打开本机 8780 页面。选择 GLIM、FAST-Planner、同步通用雷达、圆形八字及 Mesa 显示渲染，保存配置并启动，等待三组件 READY 与新鲜遥测；先显式解锁，后起飞／固定航线，最后显式降落。结束需确认落地且未解锁。本轮交付时只启动地面仿真，不替用户解锁。

代码复验（先停止实际仿真，避免单测与实飞争用）：

```bash
./scripts/env.sh env PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 /usr/bin/python3 -m pytest tests -q
npm --prefix web test
npm --prefix web run build
/usr/bin/python3 scripts/check_static.py
./scripts/labctl maintenance inspect
./scripts/labctl maintenance plan --output /tmp/uav-retention-review.json
```

清理前查看具体计划，再显式 `apply --plan`。实际飞行／故障复验工具为 `scripts/accept_continuous.py` 和 `scripts/accept_faults.py`，使用独占新输出目录、Mesa 配置和同一组合。30 分钟被动地面采样由 `scripts/ground_acceptance.py --duration 1800 --output <新文件>` 执行。切换代码或重建二进制后须重新生成资格，不复制旧资格记录。
